# k=8 原始无重叠方案固定规模验证

## 结论

最关键的静态判据通过：当 stencil 长度从 `k=7` 改为 `k=8` 后，无重叠方案每个 WMMA 输出 tile 的 8 个候选列全部有效，不再筛除第八列，也不再使用 shared-memory 输出暂存。

在固定 `1024x7168` 输出域中，k=8 论文式双 plane 基线和 k=8 无重叠版本完全使用相同的：

- 每 block 2,048 个有效输出；
- 3,584 个 blocks；
- 每 block 1,024 条、全局 3,670,016 条 FP64 `DMMA.8x8x4`；
- 8 个候选输出/8 个有效输出，不重复、不丢弃。

因此 k=7 无重叠方案的 `8/7` 额外 blocks 和 DMMA 在 k=8 中确实消失。

固定规模 CUDA Event 测量中，k=8 无重叠版本达到同 k=8 基线 **1.027008 倍**的有效吞吐，成对 bootstrap 95% CI 为 `[1.026796, 1.027253]`。这等价于吞吐高约 **2.701%**，总时间低约 **2.629%**。该结果只支持当前实现、GPU 和固定规模，不构成跨 k 的直接加速声明。

## 实现与静态几何

两套 kernel 都使用 FP64 WMMA `8x8x4`、8 warps/block 和两组16次三角权重累加。每 warp 处理4个完整 `8x8` 输出 tile，因此：

```text
DMMA/block = 8 warps * 4 tiles * 2 planes * 16 DMMA = 1024
```

k=8 无重叠 shared layout 保存9个连续的8列 chunk。每个输出 tile 直接读取 `(P_i, P_{i+1})`，随后用 `wmma::store_matrix_sync` 直接提交全部64个结果；不存在 k=7 实现中的 `output_tiles`、第八列筛除或七列推进。

静态 cubin 共找到64条展开的 `DMMA.8x8x4` 指令，即每个 kernel 32条；外层每 warp 四次输出 tile 循环使其运行时达到每 block 1,024条。

## 输入与 shared memory

一个 `32x64` 输出 block 数学上需要 `39x71=2,769` 个不同输入元素。为形成9个完整8列 chunk，两方案都加载 `39x72=2,808` 个物理输入元素，其中39个是结构性尾部 padding。

| 指标 | k=8 论文式基线 | k=8 无重叠 |
| --- | ---: | ---: |
| 有效输出/block | 2,048 | 2,048 |
| 物理输入元素/block | 2,808 | 2,808 |
| 数学必需输入/block | 2,769 | 2,769 |
| 物理输入/有效输出 | 1.371094 | 1.371094 |
| 数学必需输入/有效输出 | 1.352051 | 1.352051 |
| shared 输入槽/block | 4,992 | 2,808 |
| shared 槽/有效输出 | 2.437500 | 1.371094 |
| 重复 shared 输入槽 | 2,184 | 0 |
| CUDA Runtime 静态 shared memory | 39,936 B | 22,464 B |
| cubin 资源报告（含固定1 KiB） | 40,960 B | 23,488 B |
| registers/thread | 90 | 90 |
| active blocks/SM | 2 | 2 |

基线的 A plane 保存输入列 `0..63`，B plane 保存 `8..71`；重叠的56列乘39行形成2,184个第二副本，即17,472 B。无重叠版本保存同一组2,808个输入索引一次。本轮没有使用上一轮提出的 compact source + staging 或 alias；这里比较的就是原始连续 chunk idea。

在固定全局问题中，每个 kernel 物理加载 `2,808*3,584=10,063,872` 个输入元素。基线随后形成17,891,328个 shared 输入槽写入，其中7,827,456个是第二副本；无重叠版本形成10,063,872个不重复 shared 槽。

## 正确性和性能结果

`32x64` CPU reference 正确性门：

| kernel | 最大绝对误差 | 结果 |
| --- | ---: | --- |
| k=8 论文式基线 | `3.552713678800501e-15` | 通过 |
| k=8 无重叠 | `3.552713678800501e-15` | 通过 |

固定性能方法：RTX 5060 Laptop GPU、驱动592.19、`sm_120`，5次预热、21对AB/BA交替样本、每个CUDA Event窗口约150 ms。总流程耗时13.67秒，低于预先锁定的10分钟预算。

| kernel | 中位时间 | IQR | 平均时间/block | 有效吞吐 |
| --- | ---: | ---: | ---: | ---: |
| k=8 论文式基线 | 7.646934 ms | 0.003738 ms | 2.133631 us | 0.959866 GStencil/s |
| k=8 无重叠 | 7.445840 ms | 0.000595 ms | 2.077522 us | 0.985790 GStencil/s |

这里的“平均时间/block”是整次 kernel 中位时间除以3,584 blocks，用于同几何归一化，不是把单个 block 隔离运行得到的延迟。基线和无重叠的相对 IQR 分别约为0.0489%和0.0080%。第0对基线样本较慢，但21对中位数对它不敏感，未删除样本。

两者 active blocks/SM 都是2，因此本次 shared-memory 减少没有继续提高报告的 block occupancy。约2.7%的吞吐优势与较少的 shared 输入副本和写入相容，但没有硬件计数器证据把全部差异归因于某一种流量。

## k=7 参考

下面只观察方案与 stencil 尺寸是否匹配，不能把 k=7 与 k=8 的绝对时间作算法加速比较：

| stencil/方案 | 有效输出/block | blocks | DMMA/block | 总DMMA | 时间 | 吞吐 | 相对同 k 基线 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| k=7 论文基线 | 2,048 | 3,584 | 832 | 2,981,888 | 6.011731 ms | 1.220951 GStencil/s | 1.000000 |
| k=7 无重叠 | 1,792 | 4,096 | 832 | 3,407,872 | 6.824940 ms | 1.075472 GStencil/s | 0.880847 |
| k=8 论文式基线 | 2,048 | 3,584 | 1,024 | 3,670,016 | 7.646934 ms | 0.959866 GStencil/s | 1.000000 |

当前固定证据与“k=7 更适合论文重叠推进、k=8 更适合原始无重叠推进”的尺寸匹配假设一致，但还不足以外推到其他 stencil 长度、问题规模、GPU或精度。
